# Частичное многошаговое прогнозирование

Python-реализация метода Gromov & Baranov, [Prediction after a Horizon of Predictability](https://doi.org/10.1155/2023/6689371), Complexity, 2023, и сравнение на часовой нагрузке немецкой электросети.

**Точного совпадения таблиц статьи нет.** В публикации отсутствует часть входов и настроек, а некоторые её числа противоречат друг другу. Здесь сохранены реализация, явные допущения, выполненные эксперименты и сравнение с числовыми таблицами. В последнем аудите исправлено слияние Wishart-кластеров, добавлены архивный ряд Лоренца и немецкий ENTSO-E Power Statistics, проведён подбор на validation с отдельной проверкой следующих 1000 точек. [Новый эксперимент и сравнения](results/reconstruction/REPORT.md), [предыдущий аудит](results/fidelity/AUDIT.md), [предыдущий полный эксперимент](results/fidelity/REPORT.md), [первый эксперимент](results/REPORT.md).

## Торговый эксперимент: BTC/USDT

Ветка `codex/trading-risk-backtest` добавляет демонстрацию на готовой платформе **Backtesting.py** и официальных часовых свечах Binance. [Протокол](research/trading/protocol.json) задаёт выбор параметров через Optuna TPE на четырёх последовательных кварталах 2021 года и отдельный walk-forward тест 2022–2025. В каждом квартале модель обучается на предыдущих 10 000 часах. Переход от прогноза к позиции — торговая надстройка; исходная конфигурация статьи сохранена как контроль.

```bash
uv sync --locked --extra trading
uv run --extra trading python -m adis.trading.data
uv run --extra trading python -m adis.trading.experiment tune --trials 32
uv run --extra trading python -m adis.trading.evaluation
uv run --extra trading python -m adis.trading.audit
uv run --extra trading python -m adis.trading.report
uv run --extra trading pytest -q
```

Команды создают [отчёт](results/trading/test/report.html), [интерактивный бэк-тест](results/trading/test/partial_prediction_backtest.html), CSV с риском/доходностью, сделки, прогнозы и результаты проверки. Название метода — **Partial multistep prediction (Gromov–Baranov)**; здесь используются возмущённые траектории, усреднение и `rgdbscan`. Основная проверка — дневной ES95 против контроля с долей BTC по предыдущим 90 сигналам метода. Также сравниваются buy-and-hold, SMA, momentum, Donchian, RSI, управление волатильностью и Random Forest. Присутствуют проверки комиссий, задержки исполнения, случайного seed и различий между календарными годами.

**Гипотеза об особом снижении риска на BTC не подтвердилась.** На тесте 2022–2025 доходность после издержек составила −47,76%, максимальная просадка — 51,39%. У причинного контроля при близкой средней доле BTC (39,51% против 39,70%) доходность +68,10%, просадка 40,91%. Дневной ES95 метода хуже на 1,470 п.п.; парный блочный 95% интервал [0,793; 2,050] п.п. При нулевых издержках результат метода остаётся отрицательным: −27,50%. Это результат данной торговой адаптации, а не опровержение статьи о прогнозировании.

Прогнозы не используют будущие цены. Все сделки исполняются на реальных свечах после получения сигнала; комиссии и проскальзывание включены. Результаты подбора замораживаются до теста; изменение данных, протокола или численного кода несовместимо с продолжением прежнего исследования. Для нового эксперимента используйте новую директорию результатов вместо смешивания артефактов. Архивы данных и численные модели восстанавливаются командами и не хранятся в Git.

## Запуск

Из корня проекта, Python 3.12+ и [uv](https://docs.astral.sh/uv/):

```bash
uv sync --locked
uv run adis --dataset all
uv run python -m adis.report
```

Первый запуск скачивает версионированный CSV OPSD. Результаты записываются в `results/fidelity/`. Полный прогон использует все 1000 шаблонов и оценивает все 1000 тестовых точек на каждом горизонте 1–100 согласно формуле (7). Для этого нужны 1099 origins; прогнозы вне test не участвуют в метриках. Калибровка завершается до самого раннего тестового origin: последние 99 значений validation не используются для настройки моделей. Истинные будущие значения использует только явно обозначенный оракул `ap`.

```bash
uv run --extra trading pytest -q
uv run ruff check adis tests
uv run adis --dataset germany
```

Для короткого самостоятельного прогона:

```bash
uv run adis --dataset lorenz --output smoke-results --horizon 10 --test-stride 100 --trajectories 4
```

`--reuse-motifs` использует сохранённые мотивы только при совпадении хеша данных, кода и настроек. Несовпадение вызывает ошибку; для пересчёта уберите этот аргумент. `--validation-stride`, `--test-stride`, `--trajectories`, `--workers`, `--seed` явно управляют объёмом эксперимента. Проверка статьи проводится на основном прогоне с параметрами по умолчанию.

`--evaluation common_origins` возвращает прежнюю оценку на 901 полном окне; `--evaluation paper` выбран по умолчанию. Для повторения аудита после полного прогона:

```bash
uv run python -m adis.fidelity validation
uv run python -m adis.fidelity controls
uv run python -m adis.fidelity radius_test
```

Аудит использует сохранённые исходные train/validation/test из первого эксперимента. В `validation` сравниваются только два явно указанных в статье радиуса совпадения, 0.01 и 0.05; исходные векторы без Wishart проверяются отдельно как вариант §3.2. В `controls` изменения кода проверяются на прежних 901 origins, чтобы отличать их эффект от изменения протокола оценки.

`radius_test` проверяет на всех прежних тестовых origins радиус 0.05 только для ряда, на котором он уменьшил validation-RMSE без снижения покрытия. Оба радиуса пересчитываются с одинаковым разбиением на группы по 64 origins и одинаковыми seed для ограничения расхода памяти. В полном эксперименте радиус задаётся `--epsilon`; по умолчанию остаётся 0.01 из Algorithm 2.

Для повторения нового поиска окружения и параметров:

```bash
for phase in prepare screen search validate freeze evaluate baselines; do
    uv run python -m adis.reconstruction "$phase"
done
uv run python -m adis.reconstruction_report
```

`prepare` скачивает закреплённые источники и заново строит мотивы. Остальные этапы используют файлы в `results/reconstruction`; `--profile` выбирает один из четырёх профилей, `--output` задаёт другую папку. `search` и `validate` читают только `development.npz`, содержащий train и допустимую часть validation. `freeze` фиксирует параметры и хеши входов всех четырёх профилей; последующие этапы завершаются ошибкой при их изменении. `evaluate` применяет сохранённый `selection.json` к прежнему test и следующему блоку `fresh`. Все варианты источников публикуются; test не выбирает источник, даты, нормировку, seed или параметры. Протокол и уточнения происхождения данных сохранены в `results/reconstruction/protocol.json`.

Для дополнительного оператора `spread` функция `calibrate_trajectory_spread` возвращает пороги по горизонтам и число доступных validation-наблюдений. Их передают как `spread_thresholds` в `trajectory_forecast` с `selection="spread"`. Размах трактуется как `max-min`; калибровка усредняет конечные размахи и умножает на явно заданный `factor`. Это отдельная техника статьи, не замена `rgdbscan`.

## Что реализовано

- Все `Kmax^(L−1)` шаблоны; в основном эксперименте `L=4`, `Kmax=10`, 1000 шаблонов. Векторы не прореживаются. Мотивы — центры Wishart-кластеров; также доступен режим исходных векторов `clustered=False`.
- Wishart с `r=11`, `μ=0.2`, плотностью r-ближайшего соседа и значимостью как размахом плотностей кластера. Завершение кластеров, удаление незначимых кластеров и шум обрабатываются по псевдокоду.
- `avg`, `wavgl`, `wavgd`, `wavgc`, `clc`, `mf`, `mfp`, `threshold_clc`, `fuzzy`, `roulette`. Три способа расчёта весов и рекурсивная передача надёжности.
- `cm`, `fp`, `ap`, `en`, `lr`, `svm`, `dt`, `knn`, `mlp`, `adblr`, `adbsvm`, `lrv`, `lrs`.
- `rg`, `rgdbscan`, `rgwshrt`: отказ в первой из трёх точек, если размах строго возрастает. Для решения используются временно рассчитанные будущие прогнозы, затем зависимые шаги пересчитываются. `dbscan`, `wshrt` аналогично анализируют число кластеров.
- Ансамбль возмущённых траекторий, среднее конечных значений, отказ по размаху, росту размаха или `wamdt`.
- Ветвление по всем кластерам и его вариант с отсечением по произведению весов. Превышение явного `max_paths` вызывает ошибку, а не скрытое ограничение числа путей.
- Синхронное сравнение траекторий, начатых раньше: `cwat`, `amd`, `wamd`. Отказ передаётся в следующие шаги.
- Все 21 комбинации из числовых таблиц статьи запущены для обоих рядов. Дополнительные перечисленные операторы доступны через API и покрыты проверками, но не выдаются за опубликованные экспериментальные строки.

Непредсказуемая точка хранится как `NaN` и не становится входом подходящего шаблона. Другие шаблоны могут обойти пропуск. Нет подстановки последнего значения, истинного будущего или другого прогнозировщика.

## Допущения при неоднозначном описании

| Деталь | Принято здесь |
|---|---|
| Координаты мотивов | Хронологический порядок согласно примеру `(2,3,4) → (y0,y2,y5,y9)` и Algorithm 2; противоречащая запись в §3.4 исправлена |
| Сосед Wishart | Сам наблюдаемый объект не считается соседом; все граничные равные расстояния включаются; сортировка стабильная |
| Нулевой радиус плотности | Машинный epsilon в радиусе; экспонента ограничена 600, чтобы плотность оставалась конечной; совпадающие точки имеют одинаковую плотность |
| Порог совпадения | Строгое евклидово расстояние `<0.01` из Algorithm 2; в тексте также встречается 0.05 |
| Передача веса UPV | Для `wavgl`, `wavgd`, `wavgc` передаётся среднее фактически использованных весов: depth, distance или их произведения, согласно единой ω в §3.4. Для невзвешенных агрегаторов используется depth |
| AP | Отказ при абсолютной нормированной ошибке `>=0.05`; validation-метки AP обучают классификаторы предсказуемости, но test truth/AP никогда не передаются обычным прогнозировщикам |
| Нормализация | Min–max только по train; test не обрезается до `[0,1]` |
| Лоренц | Начальная точка `(1,1,1)`, x-координата; RK4, `dt=0.1`, параметры `(10,8/3,28)`, 3000 отброшенных наблюдений |
| Нарезка Лоренца | Train 10 000, затем validation 1000, затем test 1000 |
| Нарезка Германии | Полный доступный указанный период: train 7984, затем validation 1000, test 1000 |
| Настройка отказов | В основном режиме 101 полное validation-окно с шагом 8 до самого раннего test origin; последние 99 validation-значений исключены из калибровки. Прежний контроль: 113 validation-окон и 901 test origin |
| DBSCAN | `eps=0.01`, `min_samples=3`; параметры в статье отсутствуют |
| Пустой результат кластеризации в `rgdbscan` | Размах центров равен `NaN`; строгий рост трёх размахов не установлен, поэтому этот критерий не отвергает точку. Отсутствие конечного UPV по-прежнему означает отказ. Для одного центра размах равен нулю. Обработка этого случая авторами не задана |
| Мода `mf` | Самая наполненная корзина шириной `cluster_eps`, среднее её значений; при равенстве выбирается меньшая корзина |
| `mfp` | Центр крупнейшего кластера плюс Gaussian noise, дисперсия `1e-5`; выбрана формула, поскольку текст одновременно говорит о равномерном шуме |
| Траектории в таблицах | 16 стохастически возмущённых путей с общим origin: промежуточные шаги через `mfp`, итог — среднее конечных значений согласно §3.5; число путей и точная конструкция семейства `trj/avg` в таблицах не заданы |
| `threshold_clc` | Кластеризация кандидатов с весом надёжности `>0.5` |
| `fuzzy` | Нормированные веса надёжности как принадлежности; крупнейшая суммарная принадлежность, взвешенный центр |
| `roulette` | Выбор кластера пропорционально сумме весов его элементов |
| `cwat` | Буквальная сумма `Σ 2^-j ξj` из §4 без дополнительного делителя; при конечном числе путей её веса не суммируются в 1 |
| `wamdt` | Явная интерпретация неформального пункта Table 6: среднее взвешенное абсолютное отклонение конечных значений ансамбля от первого пути, веса — надёжности путей; без первого пути — отказ |
| Классификатор MLP | Один скрытый слой с 8 нейронами и sigmoid по §4; в Table 6 ошибочно/неоднозначно написано «8 layers» |
| SVM, DT, kNN | Полиномиальный kernel; entropy без ограничения глубины; k=3 согласно Table 6 |
| Ансамбли | AdaBoost LR: 30 моделей, AdaBoost SVM: 10; voting/stacking из LR с `C=0.1,1,10`; неуказанные настройки явно зафиксированы |
| Энтропия кандидатов | 20 равных корзин на `[0,1]`, нормировка на `log(20)`; порог выбран по F1 на validation |
| Признаки классификаторов | Десять характеристик из §4. Число кандидатов и полный размах сохраняются для диагностики, но не передаются классификаторам |
| Диагностика ряда | Permutation entropy/Jensen–Shannon complexity: dimension=5, delay=1; Э́кман: embedding=10, matrix=4, neighbors=12, separation=20 |

Это решения для воспроизводимой реконструкции, а не восстановленные авторские параметры. Ветвление поддерживает `selection='cm'`; отсечение задаётся отдельно `prune_weight`.

Принудительный режим `fp` поддерживает `avg` и `wavgl` без классификатора отказов. Он использует ближайший мотив каждого шаблона независимо от радиуса совпадения. Сочетания с другими агрегаторами вызывают `ValueError`: нулевые distance-веса или отсутствие кластера могли бы снова привести к пропуску и нарушить смысл принудительного прогноза.

`trajectory_forecast` принимает `aggregation='avg'`: это агрегирование конечных точек путей. Промежуточные шаги используют `mfp`, как предписано для возмущённых траекторий в §3.5. Другие значения вызывают ошибку вместо молчаливого игнорирования настройки.

## Протокол сравнения

Все модели обучаются до одного `train_end`, настраиваются до `calibration_end` и проверяются на одних и тех же `(origin, horizon)`. `calibration_end−1` не позже самого раннего тестового origin. Тестовые будущие наблюдения внутри окна запрещены. При переходе к следующему origin уже случившиеся значения доступны всем моделям. Масштабирование не использует validation/test.

Ошибка частичного прогноза без покрытия не интерпретируется. Пустая маска даёт неопределённые RMSE/MAE/MAPE; буквальный функционал `I2` из статьи в этом случае равен 0. MAPE вычисляется без искусственного epsilon в знаменателе; при истинном нуле она неопределённа. Дополнительно для Германии сохранены исходные МВт и MAPE на исходной нагрузке.

Обычные модели оцениваются и на полной выборке, и на **точной маске каждого частичного метода**. В таблицах также сохранены precision/recall/F1 отдельно для предсказуемых и непредсказуемых точек. `paper_*` — предполагаемая переставленная конвенция публикации, а не замена стандартных определений.

`ridge_30` использует 30 последних значений, как метод статьи. Остальные регрессоры получают 33 лага из последних 168 значений. Для Германии все эти регрессоры, включая `ridge_30`, дополнительно получают известные циклические календарные признаки; метод статьи их не получает. Поэтому `ridge_30` контролирует длину истории, но не полное равенство признаков. Сезонные прогнозы используют 24/168 часов. `dlinear_ridge` получает только все последние 168 значений, moving average 25 с повторением краёв и две линейные головы на сезонной и трендовой частях; головы обучаются совместно Ridge. Это модификация оптимизации DLinear, а не заявление о точной репликации чужой нейросети.

Опубликованный MAPE сопоставлен с MAPE как долей, без умножения на 100. В Table 3 только один заголовок содержит знак процента, а графики подписаны MAE; формула MAPE не дана. Конвенцию единиц авторов подтвердить нельзя. В выгрузке отдельно присутствуют MAE, MAPE-доля и MAPE-проценты.

Параметры регрессоров перебираются только на validation, результаты выбора — `baseline_validation.csv` (и `dlinear_validation.csv` для отдельного добавочного запуска). Обучение на train+validation после выбора не выполняется.

## Артефакты

- `results/fidelity/{lorenz,germany}/split.npz`: исходный ряд, нормированный ряд, точные origin/target индексы и истинные значения. `truth=NaN` отмечает позиции вне test; это исключение из оценки, а не отказ метода.
- `*.npy`: отдельная матрица прогнозов каждого метода, строки — общие origin, столбцы — горизонты 1–100.
- `metrics.csv`, `summary.csv`, `matched_masks.csv`: ошибки, покрытие, сопоставление на принятых точках.
- `paper_comparison.csv`: каждое опубликованное значение, измерение, абсолютная разница, допуск округления и статус сравнимости. Допуски: 0.5 процентного пункта для NP, 0.005 для остальных величин. Undefined не считается совпадением или измеренной ошибкой.
- `metadata.json`, `checksums.json`: настройки, версии, хеши данных и результатов.
- `selector_training.npz`: validation-признаки и оракульные метки.
- `diagnostics.json`, `horizons.png`, `horizons.pdf`: диагностика и кривые ошибки/покрытия.
- `references/published_tables.csv`: 168 вручную сверенных строк Tables 1–4. Жирные цифры Tables 1 и 3 проверены по изображениям PDF, поскольку `pdftotext` их теряет.
- `results/fidelity/audit/{validation,controls}.csv`: диагностика радиусов и контроль исправлений на исходной выборке. Для частичных методов сохранена также ошибка на пересечении принятых точек до/после.

- [Gromov & Baranov, 2023](https://doi.org/10.1155/2023/6689371), [PDF ВШЭ](https://publications.hse.ru/pubs/share/direct/861165160.pdf). Копия статьи в `references/paper.pdf`, © 2023 авторы, CC BY.
- [OPSD 2020-10-06](https://data.open-power-system-data.org/time_series/2020-10-06/), первичные данные ENTSO-E Transparency. URL, колонка и SHA-256 сохранены в `data/germany_source.json`.
- [Wang, Lahmiri & Bekiros, 2025](https://www.mdpi.com/1999-4893/18/11/695): прогнозирование на OPSD 2020-10-06, семейства DNN/kNN/DT. Использованы семейства моделей, а не их числа с другой нарезки.
- [Aksoy, 2026](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/rpg2.70378): сезонные модели и DLinear на европейских сетях; источник для дополнительного сравнения.

Read-only рецензирование выполнено GPT Astra: проверены Wishart независимой реализацией, DBSCAN против sklearn, кандидаты полным перебором, временная нарезка, метрики и отсутствие будущих наблюдений в обычных прогнозах.

Оценка Э́кмана на 10 000 наших значений Лоренца отдельно сравнена с upstream [`nolds.lyap_e`](https://raw.githubusercontent.com/CSchoel/nolds/master/nolds/measures.py): максимальная разница спектров `5.42e-14`. Это проверяет соответствие реализации при выбранных настройках, но не точность восстановления физического показателя системы. Результат ≈3.493 не заменяется опубликованным 0.92. Подробности сверок — `references/verification.json`.
